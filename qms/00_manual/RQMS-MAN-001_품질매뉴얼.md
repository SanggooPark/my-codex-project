## 0. 이 매뉴얼의 사용법

이 매뉴얼은 조직의 철도용 품질경영시스템(이하 RQMS)의 최상위 문서이며, ISO 22163:2023
요구사항이 어디에서 어떻게 충족되는지를 지정한다. 요구사항의 상세 이행 방법은
2단계 문서인 프로세스 기술서(`qms/20_processes/`)에 있고, 실제 운영과 증거는
RQMS 정보시스템(`src/rqms/`)이 담당한다.

세 층이 서로 어긋나지 않도록, 조항-프로세스-통제-지표-증거의 매핑은
`src/rqms/data/` 의 레지스트리 한 곳에만 둔다. 매뉴얼과 프로세스 기술서는 그
레지스트리를 인용하며, 프로세스 기술서와 성과지표 정의서는 레지스트리에서 생성된다.

| 층 | 위치 | 역할 |
| --- | --- | --- |
| 1단계 방침·매뉴얼 | `qms/00_manual/`, `qms/10_policy/` | 의도와 구조 선언 |
| 2단계 프로세스 기술서 | `qms/20_processes/` | 프로세스별 이행 방법 (4.4.3) |
| 3단계 지침·서식 | `qms/30_templates/` | 작업 수준 지침과 기록 서식 |
| 4단계 지표 정의 | `qms/40_indicators/` | PI/KPI 정의 (9.1.1.1.1, Annex C) |
| 운영·증거 | RQMS 정보시스템 | 통제 강제, 기록 보유, 적합성 보고 |

## 1. 적용범위 (4.3, 4.3.1)

### 1.1 제품 및 서비스

조직은 철도차량용 출입문 시스템의 설계·개발, 제조, 시운전 지원, 보증 및 유지보수
지원을 제공한다. RQMS 는 이 범위의 전 수명주기(입찰 → 프로젝트 → 설계·개발 → 조달 →
생산 → 출하 → 인도 후 활동)에 적용된다.

### 1.2 비적용 조항

비적용으로 선언하는 조항은 정당화 사유와 함께 `governance_record(kind='rqms_scope')`
에 등록한다. 시스템은 정당화 사유 없는 비적용과, Annex A.1 필수 프로세스의 비적용을
거부한다(CTL-037).

현재 판에서 비적용 조항은 없다. 8.8.3(안전 관리 프로세스)은 조직이 안전관련
전기·전자·프로그래머블 전자 제품을 공급하므로 **적용**된다.

### 1.3 적합성 확인 방법

```bash
python -m rqms conformity          # 조항별 적합/갭
python -m rqms clause 8.9.1        # 개별 조항의 통제·증거 현황
python -m rqms report --out rqms-report.html
```

## 2. 조직 상황 (4.1, 4.2)

### 2.1 내·외부 이슈와 이해관계자

내·외부 이슈와 이해관계자의 요구사항은 `context_entry` 등록부에서 관리하며 정기적으로
검토한다(4.1, 4.2). 프로세스 검토(9.4 i)와 경영검토(9.3.2 b)의 입력이 된다.

### 2.2 사업계획 (4.1.1.1)

전략 방향 수립 시 사업계획을 고려하며, 최소한 요약 사업계획을 문서화하고 연 1회
검토한다. 사업계획은 4.1.1.1 a)~l) 항목을 모두 다루어야 하고, 항목 누락은
시스템이 거부한다(CTL-036).

### 2.3 사회적 책임 (4.1.2)

ISO 26000 핵심 주제(조직 거버넌스, 인권, 노동관행, 환경, 공정운영관행, 소비자 이슈,
지역사회 참여·발전)를 고려하고 그 선언을 문서화한다.

### 2.4 프로세스 접근법 (4.4)

RQMS 는 Annex A 의 필수 프로세스 23개와 권고 프로세스 6개로 구성되며, 계층구조는
`qms/20_processes/README.md` 에 있다. 각 프로세스는 다음을 갖추지 않으면 운영할 수
없다(CTL-038, CTL-039).

- 4.4.1 a)~e): 입력·출력, 순서와 상호작용, 판정기준과 성과지표, 필요자원, 책임과 권한
- 4.4.3 f): 리스크기반 통제기준 (예: FMEA, SWOT)
- 승인된 프로세스 기술서와 프로세스 오너
- 프로세스 교육 및 이해 증거 (4.4.3 c, 7.2.1.1 d) 2))

## 3. 리더십 (5장)

### 3.1 품질 및 제품안전 방침 (5.2)

방침은 `RQMS-POL-001` 이며, 5.2.3 에 따라 **고장 예방**, **고객 기대**, **안전 측면**을
반드시 포함한다. 항목 누락은 시스템이 거부한다(CTL-040).

### 3.2 역할·책임·권한 (5.3)

| 항목 | 지정 방식 | 근거 |
| --- | --- | --- |
| KPI 지정 | 최고경영자가 KPI 를 지정하고 레지스트리에 등록 | 5.3.1 a) |
| 프로세스 오너 임명 | `process_instance.owner_id` | 5.3.1 b), 5.3.2 |
| 책임·권한 변경 통보 | 문서 개정 및 의사소통 기록 | 5.3.1 c) |
| 공정·생산 정지 권한 | 프로세스 실행으로부터 독립된 대표자를 임명 | 5.3.1 d) |

정지 권한자는 정지 대상 조직과 동일 소속일 수 없으며, 시스템이 이를 검증한다(CTL-031).

### 3.3 프로세스 오너의 책임

프로세스 오너는 자원 가용성(4.4.1 d)을 제외한 4.4 요구사항에 대한 프로세스 적합성을
책임지고, 프로세스 검토를 주재한다(5.3.2, 9.4 h).

## 4. 기획 (6장)

### 4.1 리스크 및 기회 (6.1)

리스크·기회는 `risk_entry` 등록부에서 관리한다. 등급이 조치 기준(9) 이상이면 조치·책임자·
기한이 필수이고, 프로젝트 범위의 리스크·기회는 비용편익 분석이 필요하다(8.1.3.9.1 b).
정기 검토와 조치 효과성 평가를 요구하며, 효과성 평가 없는 종결을 거부한다(CTL-042).

### 4.2 사업연속성 (6.1.4)

사업 리스크 평가에 근거해 사업연속성 계획을 수립하고, 검증(주기적 시험 등)하며 연 1회
검토한다. 6.1.4 NOTE 1 의 10개 리스크 범주를 모두 다루고 조치 책임을 정의해야
한다(CTL-034).

### 4.3 품질목표 (6.2)

품질목표는 측정 가능해야 하고(6.2.1 b), 자원·책임자·기한·평가방법을 정의해야
한다(6.2.2 b~e). 안전 목표를 최소 1개 포함한다(9.3.3.1 a). 미달 시 시정조치가
필수이며 시스템이 이를 강제한다(CTL-020, CTL-043).

### 4.4 변경의 기획 (6.3)

RQMS 변경은 변경관리 프로세스(8.1.4.2)를 통해 계획적으로 수행한다.

### 5.1 측정자원 통제 (7.1.5)

교정 주기가 경과하거나 부적합 판정된 측정자원은 검사·시험에 사용할 수 없다. 부적합
판정 시 이전 측정결과에 대한 소급 영향평가를 수행한다(7.1.5.2).

### 5.2 역량 통제 (7.2)

필요역량을 충족하지 않은 인원에게는 해당 업무를 배정할 수 없다. 배정 시도는 거부되고
역량 갭이 자동으로 등록되어 교육 계획의 입력이 된다(7.2.1.1 b, c).

### 5.3 문서화된 정보 통제 (7.5)

- 초안 → 검토 → 승인 순서를 강제하고, 작성자는 승인자가 될 수 없다(CTL-001).
- 승인 시점에 문서 내용의 해시 봉인을 생성하여 무단 변경을 탐지한다(CTL-002, 7.5.3.2).
- 기록은 기록 유형과 보존기간이 정의되어야 하며, 보존기간 만료 전 폐기는
  거부된다(CTL-003, 7.5.3.3 d).

## 6. 운용 (8장)

### 6.1 입찰 관리 (8.1.2)

요구사항의 조항별 검토(8.2.5 e) 1))가 완료되지 않으면 입찰 제출과 계약 수락을 할 수
없다(CTL-008). 입찰 검토는 요구사항 관리, 통제의 유형과 정도, 리스크·기회의 금액 평가,
조직 지식 입력, 인도물 원가 계획, 자원 계획, 견적 승인을 모두 포함한다.

### 6.2 프로젝트 관리 (8.1.3)

게이트 방식으로 단계를 관리하며, 아래를 강제한다.

### 6.3 형상관리 및 변경관리 (8.1.4)

- 제품분할구조를 LLRU 까지 정의하고, 최소한 안전관련 형상항목을 식별한다. 안전관련
  항목은 추적성 식별 기준이 필수다(CTL-007).
- 동결된 형상 기준선은 승인된 변경요청 없이 변경할 수 없고, 변경은 형상상태 기록으로
  남는다(CTL-006, 8.1.4.1.1 e, f).
- 변경은 영향분석·제안검증·승인을 거친 뒤에만 실행하고, 실행 후 검증한다(CTL-027).
  고객·외부공급자 요구사항에 영향을 주는 변경은 통보·합의가 선행되어야 한다(CTL-028).
- 기술 변경은 기납품 영향, 재유효성확인 판단, 대상 일련번호를 기록한다(8.1.4.2 l, n, o).

### 6.4 요구사항 관리 (8.2)

요구사항은 Annex B 범주(기능·성능·통합·비기능·비기술·RAMS·LCC·단산·중요특성)로
분류하고, 조항별로 적합성을 확인한다. 기술 요구사항은 검증·유효성확인 방법이 정의되어야
검토를 완료할 수 있다. 기술규격은 기능·비기능·RAMS·중요특성 범주를 모두 담아야
확정된다(CTL-008, CTL-046).

### 6.6 외부공급 관리 (8.4)

- 외부공급자는 분류 → 평가 → 승인 순서를 거치며, **승인된 공급자만** EPPPS 를 공급할 수
  있다(CTL-011, 8.4.1.1.4).
- 신규·변경 EPPPS 는 FAI 승인, 최초 사용 전 유효성확인, 형상 기준선 정의를 거쳐
  출시 승인한다(CTL-016, 8.4.2.1.1).
- 인수검증이 완료되지 않은 EPPPS 는 사용·투입할 수 없다. 부적합 시에는 승인된 특채
  하에서만 사용한다(CTL-012, 8.4.2.2).
- 검증활동 위임은 위임 등록부 등재와 공급자 동의 증거, 통제수단이 필요하다(CTL-013).
- 핵심 공급자는 성과 감시·재평가·등급화와 피드백, 개발 조치계획을 운영한다(CTL-048).
- 발주는 8.4.3 및 8.4.3.1 의 요구사항 12개 항목을 모두 전달해야 발행되며, 공급자
  확인서를 수령한다(CTL-049, 8.4.4 a).

| 특수공정은 공정 자격과 작업자 자격이 모두 유효할 때만 실행 — 8.5.1.3 | CTL-014 |
| FAI 승인·공정 유효성확인 없이 양산 출시 금지 — 8.5.1.1.4.1, 8.9.3 | CTL-016 |
| 생산설비 개별식별·예방정비·최초 사용 전 유효성확인·주기 재검증 — 8.5.1.4.1 | CTL-051 |
| 식별·상태 불명 품목은 부적합품으로 관리 — 8.5.2.1 | CTL-015 |
| 추적성 요구 품목은 보증종료까지 추적성 유지 — 8.5.2.1 | CTL-032 |
| 보존 규격(표시·취급·청정·유효기간·환경) 문서화, 고객·공급자 소유물 추적 — 8.5.3.1, 8.5.4.1 | CTL-052 |
| 인도 후 활동의 기술문서 갱신 및 승인된 수리지침 — 8.5.5.1 | CTL-059 |

### 6.8 출하 (8.6)

계획된 검사·시험이 만족스럽게 완료되지 않으면 출하할 수 없고, 출하하려면 고객 특채가
필요하다(CTL-017). 출하 기록에는 합격기준 적합 증거와 출하 승인자를 남긴다(8.6 a, b).
검사·시험 기록에는 실제 결과 데이터를 기록한다(8.6.1).

### 6.9 부적합 출력 및 특채 (8.7)

- 부적합은 등록부에 등록하고 처리방법(시정·재작업·수리·폐기·격리·반품·특채)과 결정
  권한자를 기록한다(8.7.2 d).
- 특채는 승인수량과 유효기간이 필수이며, 유효기간 만료 또는 수량 초과 시 제품을 더
  이상 사용할 수 없다(CTL-018, 8.7.3 f).
- 고객승인이 필요한 특채는 인도 전 고객승인을 받아야 하고, 외부공급자 특채는 고객 제출
  전 내부 승인이 선행되어야 하며, 제품 식별 방법을 고객과 합의하고 적합성 선언서에
  기재한다(CTL-019, 8.7.3 g).

### 6.10 RAMS 및 LCC (8.8)

- RAM 관리 프로세스는 입찰·설계 단계의 산정, 설계·공급망 반영, 현장 데이터 수집,
  분석·비교, 설계 및 외부공급자 환류, 목표 감시를 포함한다(8.8.2 a~g).
- RAM 목표 미달 시 현장 데이터 분석, 시정조치, 설계 환류가 필수다(CTL-029, 8.8.2 g).
- 안전관련 제품은 안전 관리 프로세스를 운영하고 적용 표준(IEC 62278, 62425, 62279 등)을
  식별하며 안전 케이스와 위험원 기록을 보유한다(CTL-057, 8.8.3).
- LCC 관리 프로세스는 권고사항으로 운영한다(8.8.4).

### 6.11 초도품 검사 (8.9)

FAI 는 계획 → 사전조건 평가 → 검사·검증(중요·특수공정 중점 공정검토 포함) → 결정
(승인/조건부/거부) → 시정조치 후속 순서로 수행한다. 조건부 승인 또는 거부 시 시정조치
연계가 필수다(8.9.1 e). FAI 는 내부 제품과 EPPPS, 생산설비 유효성확인, 생산공정
유효성확인, 프로세스 이전에 적용한다(8.9.3).

### 6.12 단산 관리 (8.10)

최소한 보증 종료 시점까지 공급 제품과 예비품의 가용성을 보장하는 단산 관리계획을
수립하고 정기 검토한다. 단산 리스크를 평가하고 고위험 항목은 완화조치와 고객
의사소통을 요구한다(CTL-030).

### 6.13 프로세스 이전 (8.1.1.2)

프로세스 이전은 타당성조사, 리스크 평가, 조치계획, (필요 시) 고객 통보, FAI, 기록 보유를
갖추고 변경관리와 연계되어야 승인된다(CTL-035).

## 7. 성과평가 (9장)

### 7.1 성과지표 (9.1.1.1)

모든 PI 정의는 9.1.1.1.1 a)~g)(관련 프로세스, 산식, 목표·기간, 측정 제공자, 보고 시점과
대상, 조치 정의 책임자, 데이터 출처)를 완비해야 한다(CTL-056). 9.1.1.1.1 h)~o) 의 8개
필수 측정 항목과 9.1.1.1.2 의 권고 항목을 포함하며, 모든 프로세스는 최소 1개 지표를
갖는다(4.4.1 c). 정의서는 `qms/40_indicators/RQMS-PI-001_성과지표정의서.md` 이다.

### 7.2 분석 및 평가 (9.1.3)

KPI 목표 미달 시 시정조치가 필수이고(CTL-020), 분석 결과는 추세와 함께 관련
이해관계자에게 공유한다(9.1.3.1).

### 7.3 고객만족 (9.1.2)

고객 불만은 기록하고, 접수 통보 및 시정조치 연계 후 회신하며, 공통 해결책과 교훈이
공유되도록 한다(CTL-053, 9.1.2.1).

### 7.4 내부심사 (9.2)

- 모든 프로세스와 이 표준의 요구사항은 **3년 내 최소 1회** 심사한다(CTL-021, 9.2.3.2 c).
- 심사원은 자신의 업무(소속 프로세스)를 심사할 수 없다(CTL-022, 9.2.3.2 d).
- 심사팀은 심사원칙, 심사범위, 해당 조항, 심사기준 지식과 심사 경험을 갖춰야
  한다(CTL-055, 9.2.3.3.1).
- 중·경부적합 발견사항은 지체 없이 시정조치와 연계한다(9.2.2 e).

### 7.5 경영검토 (9.3)

- 연 1회 실시하며, 중대 품질사고 또는 RQMS 중대 변경 시 추가 경영검토를
  실시한다(CTL-023, 9.3.1.1).
- 입력은 9.3.2 a)~f) 와 9.3.2.1 a)~e)(프로젝트검토 핵심이슈, 프로세스검토 결과, 전
  KPI/PI 분석, 내·외부 실패의 안전 영향, 사업계획 출력)를 모두 포함해야
  한다(CTL-054).
- 출력은 9.3.3 a)~c) 와 9.3.3.1 a), b)(목표 달성, 고객만족)를 포함하고, 목표 미달 시
  시정조치를 관리한다.

### 7.6 프로세스 검토 (9.4)

필수 프로세스는 경영검토와 연계하여 연 1회 검토한다(CTL-024). 검토는 9.4 a)~l) 항목을
모두 다루고, 프로세스 오너가 주재하며 내부 이해관계자 대표가 참여하고 결과는
최고경영자에게 보고된다.

## 8. 개선 (10장)

부적합 발생 시 대응·원인분석·조치·효과성 검토를 수행하고, 유사 부적합의 존재·발생
가능성을 확인한다(10.2.1). 시정조치 필요성 평가 기준과 문제해결 기법(4D·8D·FRACAS),
감시, 에스컬레이션 기준을 적용한다(CTL-033, 10.2.3). 효과적이지 않은 시정조치는
종결할 수 없다.
