# RQMS — ISO 22163:2023 철도용 품질경영시스템

ISO 22163:2023 *Railway applications — Railway quality management system* 의
요구사항을 **문서체계 + 실행 시스템**으로 함께 구축한 저장소입니다.

품질경영시스템은 문서만으로는 성립하지 않고, 시스템만으로도 성립하지 않습니다.
이 저장소는 두 축을 하나의 진실원천에 묶습니다.

| 축 | 위치 | 역할 |
| --- | --- | --- |
| 표준 레지스트리 | `src/rqms/data/` | 조항 170개, Annex A 프로세스 29개, 지표 21개, 통제 60개 |
| QMS 문서체계 | `qms/` | 품질매뉴얼, 방침, 프로세스 기술서, 기록 서식, 지표 정의서 |
| 실행 시스템 | `src/rqms/` | 프로세스 업무 로직, 통제 강제, 등록부, 적합성 보고 |

프로세스 기술서와 지표 정의서는 레지스트리에서 **생성**되므로 문서와 시스템이
어긋날 수 없습니다.

---

## 빠른 시작

```bash
export PYTHONPATH=src                      # 또는 pip install -e .

python -m rqms init --db rqms.db --seed    # DB 생성 + 시연 조직 데이터 구축
python -m rqms conformity --db rqms.db     # 조항별 적합성 평가
python -m rqms check --db rqms.db          # 통제 상태 점검
python -m rqms report --db rqms.db --out rqms-report.html
```

`--seed` 는 가상의 철도차량 부품 제조사 "한빛레일"의 RQMS 를 입찰 → 프로젝트 →
설계 → 조달 → 생산 → 출하 → 인도 후 활동 → 성과평가 → 심사 → 경영검토 순서로
**실제 서비스 API 를 호출해** 구축합니다. 즉 시연 데이터는 모든 통제를 실제로
통과한 상태이며, 구축 직후 적합성 평가는 갭 0 을 보고합니다.

```
ISO 22163:2023 적합성 평가 — 기준일 2026-09-18
  조항 총계            : 170
  적용 조항            : 170
  적합                 : 170
  갭                   : 0
  적합률               : 100.0%
  필수(shall) 적합률   : 100.0%
  통제 위반            : 0건 (중 0 / 경 0)
```

## 설계 원리

### 1. 요구사항을 데이터로 둔다

`src/rqms/data/clauses/*.json` 이 4~10장의 조항 170개를 담고, 각 조항마다
의무(shall/should), 출처(ISO 9001 본문 / ISO 22163 추가), 관련 프로세스,
요구되는 문서화된 정보, 구현 모듈, 강제 통제를 지정합니다.

```json
{
  "id": "8.1.3.1.3",
  "title_ko": "프로젝트 문서화된 정보 및 단계검토(미결사항 종결 요건)",
  "obligation": "shall",
  "source": "iso22163",
  "processes": ["PRJ"],
  "documented_info": ["phase_review_record", "project_record"],
  "modules": ["rqms.services.projects"],
  "controls": ["CTL-004"]
}
```

레지스트리는 로드 시점에 상호 참조 정합성을 검증합니다 — 미정의 프로세스·통제·조항
참조, 어떤 조항도 참조하지 않는 통제, 성과지표가 없는 프로세스(4.4.1 c 위반)는
모두 로드 실패로 처리됩니다.

### 2. 요구사항을 코드가 강제한다

통제 60개 중 31개는 `invariant` 로, 업무 처리 시점에 서비스 계층이 강제합니다.
위반은 예외로 거부되고 `control_violation_log` 에 남습니다.

```python
>>> suppliers.issue_purchase_order(db, po_no="PO-1", supplier_code="SUP-NEW", ...)
ControlViolation: CTL-011 [조항 8.4.1.1.1, 8.4.1.1.4, 8.1.3.10]:
  공급자 SUP-NEW(신규협력사) 는 승인되지 않았습니다.
  EPPPS 는 승인된 공급자만 공급할 수 있습니다(8.4.1.1.4).
```

대표적인 강제 통제:

| 통제 | 내용 | 조항 |
| --- | --- | --- |
| CTL-001 | 승인되지 않은 문서의 배포·사용 금지, 작성자 ≠ 승인자 | 7.5.2, 7.5.3 |
| CTL-002 | 승인 기록의 해시 봉인 및 무단 변경 탐지 | 7.5.3.2 |
| CTL-004 | 이전 단계 미결사항 미종결 시 단계검토 통과 금지 (최고경영자 승인 시 예외) | 8.1.3.1.3 d) |
| CTL-008 | 요구사항 조항별 검토 전 입찰 제출·계약 수락 금지 | 8.2.5 e) 1) |
| CTL-011 | 승인된 외부공급자만 EPPPS 공급 | 8.4.1.1.4 |
| CTL-014 | 특수공정은 공정·작업자 자격이 모두 유효할 때만 실행 | 8.5.1.3 |
| CTL-016 | FAI 승인 전 양산 출시 금지 | 8.9.3 |
| CTL-017 | 계획된 검사·시험 미완료 시 출하 금지 (특채 예외) | 8.6.1 |
| CTL-018 | 특채 유효기간 만료·수량 초과 시 사용 금지 | 8.7.3 f) |
| CTL-020 | KPI 목표 미달 시 시정조치 필수 | 9.1.3.1 |
| CTL-025 | 교정 주기 경과 측정자원 사용 금지 | 7.1.5.2 |
| CTL-026 | 역량 미충족 인원 업무 배정 금지 | 7.2 |

나머지 29개는 `audit` 통제로, 시스템 상태 전체를 점검합니다 — 3년 심사 커버리지
(9.2.3.2 c), 자기업무 심사 금지(9.2.3.2 d), 경영검토 주기(9.3.1.1), 프로세스 검토
주기(9.4), 단산 관리계획 검토(8.10) 등.

### 3. 적합성을 증명 가능하게 만든다

조항 하나의 적합 판정은 세 조건을 모두 만족할 때만 내려집니다.

1. 구현 모듈이 존재하고 임포트 가능한가
2. 연결된 강제 통제에 위반이 없는가
3. 요구되는 문서화된 정보(증거)가 실제 등록부에 존재하는가

```bash
$ python -m rqms clause 8.7.3
[8.7.3] 부적합 출력 관리 프로세스 관리(등록부·특채 등록부·만료·고객승인)
  의무     : shall (iso22163)
  프로세스 : NCO, NCA
  구현     : rqms.services.nonconformity
  통제     :
    - CTL-018 [invariant/major] 특채의 유효기간 만료 또는 승인수량 초과 시 사용 금지
    - CTL-019 [invariant/major] 고객승인 대상 특채는 인도 전 고객승인 필수 …
  증거     :
    [O] 부적합 등록부 (nonconformity_record)
    [O] 특채 등록부 (concession_register)
```

## CLI

| 명령 | 용도 |
| --- | --- |
| `init --seed` | DB 생성 및 시연 RQMS 구축 |
| `conformity` | 조항별 적합성 평가 및 갭 목록 (갭이 있으면 종료코드 1) |
| `check [--control ID]` | audit 통제 상태 점검 |
| `matrix clause\|control\|process` | 추적성 매트릭스 |
| `clause <번호>` | 조항 상세 — 통제·구현·증거 현황 |
| `indicators [--period]` | PI/KPI 스코어카드 |
| `register <이름>` | 등록부 조회 (문서, 부적합, 특채, 시정조치, 심사 등 30종) |
| `processes` | Annex A 프로세스 계층구조 |
| `report --out FILE` | HTML 적합성 보고서 |

모든 명령은 `--json` 으로 기계 판독 출력을 지원하므로 CI·대시보드에 연결할 수 있습니다.

위반을 거부하는지, 시연 시스템이 갭 0 을 유지하는지, 레지스트리 정합성이 깨지지 않는지를
검증합니다.

```bash
python tools/generate_qms_docs.py --check   # 문서-레지스트리 동기 확인
```

## 범위 및 한계

- 이 저장소는 조직의 RQMS 를 **운영하고 적합성을 입증하는 시스템**입니다. 인증
  취득 여부는 인증기관의 심사 결과에 따릅니다.
- ISO 22163:2023 본문은 저작권 자료이므로 저장소에 포함하지 않습니다. 레지스트리는
  조항 번호와 요구사항 요지, 조직의 이행 방식만 담습니다.
- 시연 데이터의 조직·제품·고객은 모두 가상입니다.
- 조직 고유의 값(품질목표 수치, 심사 주기, 에스컬레이션 임계값, 보존기간 등)은
  `src/rqms/data/` 와 각 서비스 모듈 상단의 상수에서 조정합니다.
